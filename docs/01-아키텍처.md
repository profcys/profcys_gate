# 1. 시스템 아키텍처 (PROFCYS Gateway)

## 1.1 구성 요약

```
 사용자 브라우저 (PC·태블릿·모바일, PWA)
   │  https://profcys.web.app   ← Firebase Hosting (무료) : React SPA 정적 파일만 제공
   │
   │ ① API 호출: POST text/plain {action, params, token}   (CORS 사전요청 없음, 토큰은 본문 전송)
   ▼
 Apps Script "PROFCYS Gateway API" 웹앱 (무료, 소유자 권한 실행)
   │  ② Firestore REST  (ScriptApp OAuth 토큰, 서비스 계정 키 불필요)
   │  ③ Identity Toolkit REST (Firebase Authentication 이메일/비밀번호 — 비밀번호 검증·변경 전용)
   ▼
 Firebase 프로젝트 profcys (Spark 무료 요금제)
   ├─ Firestore : users, services, sessions, logs, stats …  (브라우저 직접 접근 전면 차단)
   └─ Authentication : 비밀번호 해시 보관 (PROFCYS 는 비밀번호를 저장하지 않음)

 기존 업무 Apps Script 4종 ──④ sso.verify / sso.check (서버 간, 서비스 키)──▶ Gateway API
```

| 구성 요소 | 기술 | 비용 |
|---|---|---|
| 프런트엔드 | React 19 + TypeScript + Vite, PWA | Firebase Hosting 무료 할당량 |
| API 서버 | Google Apps Script 웹앱 (V8) | 무료 (일일 할당량 내) |
| 데이터베이스 | Cloud Firestore (Native, 서울 리전 권장) | Spark 무료 할당량 |
| 인증 | Firebase Authentication (이메일/비밀번호) — 내부 전용 이메일 사용 | 무료 |
| 실시간 반영 | `public/revision` 문서 구독(onSnapshot) 또는 90초 폴링 | 무료 |
| 업무 서비스 SSO | `ProfcysAuth.js` 공통 모듈 (각 Apps Script에 추가) | 무료 |

Cloud Functions(Blaze 요금제 필요)는 **사용하지 않습니다.** 서버 로직은 모두 Apps Script에서 실행되므로 월 운영비 0원 구조입니다.

## 1.2 무료 구조 vs 유료 구조 비교

| 항목 | 현재(무료) 구조 | 유료 전환 시(선택) |
|---|---|---|
| API | Apps Script 웹앱 (응답 0.5~2초, 동시 실행 30) | Cloud Functions/Cloud Run (응답 100ms대, 자동 확장) |
| 할당량 | UrlFetch 20,000회/일(개인 계정), 실행 시간 6분/요청 | 사실상 제한 없음 (사용량 과금) |
| 사용자 규모 | 동시 수십 명, 일 수백 명 수준 적합 | 수천 명 이상 |
| 관리자 승인 | 불필요 | **Blaze 요금제 전환 필요 → 관리자 사전 승인 필수** |

유료 전환은 이 프로젝트에서 하지 않았으며, 관리자 승인 없이 결제 계정을 연결하거나 유료 서비스를 활성화하지 않습니다.

## 1.3 Firestore 데이터 구조

| 컬렉션 | 문서 ID | 주요 필드 | 비고 |
|---|---|---|---|
| `users` | uid(난수) | username, displayName, organization, role, status, allowedServices[], delegatedServices[], groups[], validFrom/Until, mustChangePassword, sessionsValidAfter | 비밀번호 없음 |
| `usernameMappings` | 아이디(소문자) | uid, authEmail(`u<난수>@profcys.firebaseapp.com`) | 아이디 → 인증 계정 연결 |
| `services` | serviceId | serviceName, url, status, accessPolicy, openMode, integrationStatus, directAccess, securityVerified, sortOrder, version … | 서비스 = DB 데이터 |
| `serviceSecrets` | serviceId | keyHash(SHA-256), lastSsoSuccessAt | 서비스 키 원문 미보관 |
| `serviceCategories` | categoryId | categoryName, icon, color, sortOrder | |
| `announcements` | 자동 | title, content, category, priority, targetRoles, targetServices, 기간 | |
| `settings` | platform / ui / system | 시스템 설정·화면 구성·초기화 정보·삭제된 서비스 ID | |
| `authSessions` | SHA-256(세션 토큰) | uid, createdAt, lastActivityAt, expiresAt, revoked, ttlAt | 토큰 원문 미보관 |
| `authCodes` | SHA-256(SSO 코드) | uid, serviceId, sessionHash, expiresAt, used | 60초·1회용 |
| `loginGuards` | SHA-256(아이디) | failures, lockedUntil | 무차별 대입 방지 |
| `accessLogs` / `adminLogs` / `serviceChangeLogs` | 자동 | 시각, 사용자/관리자, 작업, 결과, 변경 전·후 | 비밀번호·코드·토큰 미기록 |
| `statsDaily` | YYYY-MM-DD | loginUsers.{uid}, serviceLaunch.{sid} … (increment) | 통계 원천 |
| `userPreferences` | uid | favoriteServices, recentServices, 알림 확인 시각 | |
| `public` | revision | rev(숫자) | **유일하게 브라우저 읽기 허용** |

## 1.4 역할·권한 매트릭스

| 기능 | 최고관리자 | 운영관리자 | 일반 사용자 |
|---|:-:|:-:|:-:|
| 대시보드·허용 서비스 실행 | ✔ (활성 서비스 전체) | ✔ (권한·위임 서비스) | ✔ (권한 서비스) |
| 사용자 등록·수정·비밀번호 초기화 | ✔ | ✔ (일반 사용자만, 위임 서비스 권한만) | ✘ |
| 관리자 계정 생성·역할 변경 | ✔ (재인증) | ✘ | ✘ |
| 사용자 영구 삭제 | ✔ (재인증 + 아이디 입력) | ✘ | ✘ |
| 서비스 등록·URL 변경·공개 승인·삭제 | ✔ | ✘ | ✘ |
| 서비스 표시 정보 수정·점검 전환 | ✔ | ✔ (위임 서비스) | ✘ |
| 카테고리·화면 구성·시스템 설정·백업 | ✔ | ✘ | ✘ |
| 접속 기록·통계 | ✔ | ✔ (일반 사용자 기록) | ✘ |
| 관리자 작업 이력 | ✔ | ✘ | ✘ |

서비스 접근 판단 순서(서버 `02_Policy.js` 단일 모듈): ① 서비스별 거부 목록 → ② 최고관리자 → ③ 개별 부여(allowedServices) → ④ 운영관리자 위임 → ⑤ 서비스 정책(NONE·ADMINS·ALL·RULES). 정책 RULES는 지정한 역할·기관·그룹 조건을 **모두** 충족해야 허용합니다. 이어서 서비스 상태(공개·예약·점검·종료)를 적용합니다.

## 1.5 통합 인증(SSO) 흐름

```
사용자 ─[카드 클릭]→ 포털 ─launch→ Gateway: 세션·계정·권한·서비스 상태 재검증
                                   └ 64자리 1회용 코드 발급(60초, serviceId 고정, 해시만 저장)
포털 ─(새 탭, opener 제거, POST 폼 profcys_code)→ 업무 Apps Script doPost
업무 Apps Script ─sso.verify(code, serviceId, serviceKey)→ Gateway: 원자적 사용 처리(재사용 불가) → 사용자 정보
업무 Apps Script: 서비스 세션 생성(CacheService) → 화면 표시
보호 함수 호출마다 ProfcysAuth.require(token) → 5분마다 sso.check (권한 회수·로그아웃·비활성 즉시 반영)
```

## 1.6 화면 구성

| 경로 | 화면 | 대상 |
|---|---|---|
| `/login` | 통합 로그인 | 전체 |
| `/setup` | 최초 관리자 설정 (설정 토큰 필요) | 소유자 |
| `/recover` | 관리자 복구 (복구 토큰 필요) | 소유자 |
| `/` | 사용자 대시보드 (검색·필터·즐겨찾기·최근·신규·공지·자동 레이아웃) | 로그인 사용자 |
| `/account`, `/account/password` | 내 정보, 비밀번호 변경 | 로그인 사용자 |
| `/service/:id` | 임베딩 실행 (보안 검증된 서비스만) | 권한 사용자 |
| `/help` | 도움말 | 로그인 사용자 |
| `/admin` 이하 | 관리자 홈, 사용자, 신규 등록, 권한, 서비스, 카테고리, 화면 구성, 공지, 접속 기록, 작업 이력, 통계, 설정, 백업, QR | 관리자 |
