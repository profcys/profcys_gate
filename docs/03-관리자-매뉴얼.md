# 3. 관리자 매뉴얼

관리자 화면은 우측 상단 사용자 메뉴의 **관리자 화면** 또는 `/admin`에서 엽니다. 모든 수치와 목록은 실제 DB 기준이며, 저장 즉시 모든 사용자 화면에 반영됩니다(새로고침·재배포 불필요).

## 3.1 사용자 계정

| 작업 | 위치 | 비고 |
|---|---|---|
| 신규 등록 | 사용자 계정 관리 › 신규 사용자 등록 | 임시 비밀번호 자동 생성(권장)이며 **한 번만 표시**됩니다. 사용자는 첫 로그인 때 변경해야 합니다 |
| 일괄 등록 | CSV 일괄 등록 | 양식을 내려받아 작성하고 최대 200명까지 등록합니다. 서비스는 `common-work;mentor-matching`처럼 세미콜론으로 구분합니다 |
| 정보·권한 수정 | 목록 › ✎ | 역할 변경 시 재인증이 필요하며, 기존 세션은 자동 종료됩니다 |
| 비밀번호 초기화 | 목록 › 🔒 | 기존 비밀번호는 조회할 수 없습니다. 초기화하면 모든 세션이 종료됩니다 |
| 비활성화·활성화 | 목록 › 👤 | 삭제 대신 **비활성화**를 권장합니다 |
| 잠금 해제 | 목록 › 🔓 | 로그인 5회 실패 시 15분 동안 잠깁니다 |
| 강제 로그아웃 | 목록 › ⇥ | 즉시 반영됩니다. 연동된 업무 서비스에도 5분 안에 반영됩니다 |
| 영구 삭제 | 목록 › 🗑 (최고관리자) | 재인증과 아이디 입력이 필요하며, 접속 기록은 보존됩니다 |
| 일괄 관리 | 체크 후 상단 버튼 | 권한 추가·회수·교체, 활성/비활성, 이용 종료일 |
| CSV 내보내기 | 상단 버튼 | 비밀번호·인증 정보는 포함되지 않습니다 |

마지막 최고관리자는 삭제·비활성화·강등할 수 없습니다. 자기 자신의 역할과 상태도 바꿀 수 없습니다.

## 3.2 서비스 접근 권한

- 신규 사용자와 신규 서비스의 기본값은 **접근 불가**입니다.
- **서비스 접근 권한 관리**는 사용자×서비스 체크박스 표입니다. 서비스 열은 DB에 등록된 서비스로 자동 생성됩니다. 변경 후 **변경 사항 저장**을 누릅니다.
- 서비스별 정책은 *업무 서비스 관리 › 수정 › 접근 권한*에서 정합니다.
  - 개별 지정(기본)
  - 관리자만
  - 조건: 역할·기관·그룹을 **모두** 충족해야 합니다
  - 전체 사용자
- "전체 서비스 선택"은 현재 등록된 서비스만 선택합니다. 이후에 등록되는 서비스 권한을 자동으로 주지 않습니다.

## 3.3 업무 서비스 (코드 수정 없이 추가·변경)

1. **간편 등록**: 이름과 URL만 입력합니다. 유형·아이콘·색상은 자동으로 정해집니다.
2. **상세 등록(6단계)**: 기본 정보 → 연결 URL → 카드 디자인(실시간 미리보기) → 접근 권한 → 공개 설정 → 연동·보안.
3. 등록 직후에는 **초안(비공개)**이며 아무에게도 보이지 않습니다. 권한을 지정한 뒤 **공개 승인**합니다. 승인 체크가 필수이고, 권한자 0명이나 보안 미검증이면 경고가 표시됩니다.
4. 상태는 초안 / 공개 / 예약 공개 / 점검 중 / 비활성 / 보관입니다. 공개 종료일이 지나면 자동으로 "공개 종료"가 됩니다.
5. **URL 검증**: 다음 URL은 등록·공개가 차단됩니다.
   - https가 아닌 주소, `javascript:`·`data:` 등 위험한 형식
   - IP 주소·내부망 주소, 계정정보가 포함된 주소
   - 허용 도메인 외 주소, 중복 주소

   **연결 확인**은 참고용입니다. Google 로그인이 필요한 서비스는 "확인 불가"로 나올 수 있으며, 이것이 실패를 뜻하지는 않습니다.
6. **순서**: 행을 끌어 놓거나 ↑↓ 버튼으로 바꾼 뒤 **순서 저장**을 누릅니다. 📌로 상단 고정합니다.
7. **변경 이력**: 모든 변경의 전·후 값을 기록합니다. **이 변경 이전으로 복원** 시 다음 규칙이 적용됩니다.
   - URL은 현재 정책으로 다시 검증합니다.
   - 접근 정책과 보안 검증 상태는 현재 값을 유지합니다. 회수된 권한이 되살아나지 않습니다.
   - 공개 상태는 초안으로 복원되므로 다시 공개 승인해야 합니다.
8. **영구 삭제**는 보관 상태에서만 가능하며, 재인증과 서비스 ID 입력이 필요합니다. 삭제된 ID는 재사용되지 않고, 사용자 권한에서도 제거됩니다. **외부 Apps Script와 업무 데이터는 삭제되지 않습니다.**
9. **통합 인증 키**(🔑)는 업무 Apps Script의 SSO 연동에 사용합니다. 한 번만 표시되며, 재발급하면 이전 키는 즉시 무효가 됩니다.

### 초기 등록 서비스 (URL 변경 금지)

| ID | 이름 | 카테고리 |
|---|---|---|
| common-work | 공통작업 플랫폼 | 공통업무 |
| mentor-matching | 멘토-멘티 일정 매칭 | 멘토링 |
| startup-mentoring | 창업 멘토링 지원 | 창업지원 |
| startup-evaluation | 창업 심사 지원 | 심사 및 평가 |

연동 상태 표시는 실제 검증 결과대로만 바꿉니다.

| 단계 | 의미 |
|---|---|
| 링크 연결 완료 | 포털 권한으로 카드 표시·실행만 제어 (기존 URL 직접 접속은 가능) |
| 통합 인증 적용 (직접 접근 차단 미검증) | ProfcysAuth `monitor` 적용 |
| 완전한 통합 인증 완료 | `enforce` 적용 + 직접 URL 차단 확인 + 보안 검증 완료 (서버가 조건 미충족 시 거부) |

## 3.4 화면 구성

**화면 구성 관리**에서 다음을 설정합니다.
- 레이아웃: 자동(권장), 2·3·4열, 목록형, 컴팩트, 카테고리 그룹
- 기기별 열 수, 카드 크기·스타일, 표시 항목, 정렬, 페이지당 개수

오른쪽 미리보기에서 **PC 1280 / 태블릿 820 / 모바일 390** 화면과 예시 서비스 0~50개 상황을 확인한 뒤 저장합니다. **기본 디자인 복원**과 **변경 이력 복원**도 여기서 할 수 있습니다.

자동 레이아웃 기준(카드 최소 너비 보장, 가로 스크롤 없음):

| 표시 서비스 수 | PC 열 수 |
|---|---|
| 1개 | 1열(중앙) |
| 2개 | 2열 |
| 3개 | 3열 |
| 4개 | 2열(2×2) |
| 5~6개 | 3열 |
| 7~12개 | 3~4열 |
| 13개 이상 | 4열 + 필터 강조 |
| 21개 이상 | 카테고리 그룹 + 페이지 나누기 |

태블릿은 2~3열, 모바일은 1열입니다.

## 3.5 공지사항·카테고리·설정·백업

- **공지사항**: 분류, 중요도, 게시 기간, 대상 역할·대상 서비스 권한자를 지정합니다. 중요 공지는 대시보드 상단에 표시됩니다.
- **카테고리**: 추가, 수정, 순서 변경, 숨김을 할 수 있습니다. 삭제하면 소속 서비스는 "기타"로 이동합니다.
- **시스템 설정**: 아래 보안 항목을 바꿀 때는 재인증이 필요합니다.
  - 세션(미사용 자동 로그아웃 60분, 최대 12시간)
  - 비밀번호 정책
  - 로그인 잠금
  - 허용 도메인
  - SSO 코드 유효시간

  자체 회원가입은 항상 꺼져 있습니다.
- **백업**: JSON으로 내보내며 비밀번호·인증 이메일·세션·서비스 키는 제외됩니다. 복원 대상은 서비스, 카테고리, 공지, 화면 구성, 설정이고, **사용자 계정·권한은 복원하지 않습니다.**
  - 정기 백업: Apps Script `installMaintenanceTriggers`를 실행하면 매주 Google Sheets로 백업하고, 매일 만료 기록을 정리합니다.
- **접속 QR코드**: PNG·SVG로 저장하거나 인쇄합니다. QR에는 접속 주소만 들어가며 인증 정보는 포함되지 않습니다.

## 3.6 기록·통계

- **접속 기록**: 다음 항목을 기간, 작업, 서비스, 결과로 필터하고 CSV로 내보낼 수 있습니다.
  - 로그인 성공·실패, 로그아웃, 세션 만료
  - 서비스 실행, 서비스 인증 성공·실패
  - 권한 거부, 비밀번호 변경
- **관리자 작업 이력**: 계정·권한·서비스·설정 변경과 백업이 모두 기록됩니다(최고관리자만 조회).
- **운영 통계**: 다음 항목을 기간별로 보고 CSV로 내보냅니다.
  - 일별·주별·월별 고유 로그인 사용자
  - 서비스별 실행·인증 성공·실패·거부와 이용 비율
  - 신규·비활성 사용자

  Looker Studio 연동은 `exportStatsToSheet`가 만든 시트를 데이터 소스로 연결합니다.
