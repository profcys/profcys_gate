# 5. 운영·장애 대응·비용 가이드

## 5.1 무료 할당량과 예상 사용량 (월 운영비 0원 기준)

| 자원 | 무료 한도(요약) | PROFCYS 사용 패턴 | 여유 |
|---|---|---|---|
| Firebase Hosting | 저장 10GB, 전송 360MB/일 | 첫 방문 약 0.4MB(gzip), 이후 캐시 | 일 수백 명 충분 |
| Firestore | 읽기 5만/일, 쓰기 2만/일, 저장 1GiB | 로그인 1회 ≈ 읽기 5~8·쓰기 4~6, 대시보드 ≈ 읽기 2~4 (캐시 5분) | 일 수백~천여 회 로그인 |
| Firebase Auth | 이메일/비밀번호 무료 | 로그인·비밀번호 변경 시만 호출 | 충분 |
| Apps Script | UrlFetch 2만 회/일(개인 계정), 동시 실행 30, 요청당 6분 | API 요청 1회 ≈ UrlFetch 1~6회 | 일 3천~1만 API 요청 |
| Apps Script 트리거 | 총 90분/일 | 매일 백업·정리 1~2분 | 충분 |

> 한도 수치는 Google 정책에 따라 바뀔 수 있습니다. Firebase 콘솔 › 사용량 및 결제, Apps Script › 실행 기록에서 실제 사용량을 확인하세요.
> 한도를 넘으면 그날 남은 시간 동안 일부 요청이 실패합니다. **과금은 발생하지 않습니다**(Spark 요금제에는 결제 수단이 없음).

### 사용량 절감 장치(구현됨)
- 서버 캐시(CacheService): 서비스 목록 5분, 사용자 정보 5분, 세션 5분. 관리자 변경 시 즉시 무효화합니다.
- 활동 시간 기록은 2분 단위로 묶어 저장합니다(쓰기 절감).
- 변경 감지는 `public/revision` 실시간 구독(Firestore 무료 읽기 1회/변경)으로 하고, 불가 시 90초 폴링을 하되 숨겨진 탭에서는 중지합니다.
- 통계는 일별 문서 1개에 increment로 누적합니다(집계 쿼리 없음).
- 비활성 기록은 TTL 정책 또는 매일 정리 트리거로 삭제합니다(저장 용량 절감).

### 유료 전환이 필요한 신호 (관리자 승인 후에만)
- Apps Script "서비스 호출 횟수 초과"가 반복되는 경우
- 동시 접속이 많아 응답이 3초를 넘는 경우

이때는 Blaze 요금제로 전환하고 API를 Cloud Functions로 이전할 수 있습니다. 예산 알림 설정은 필수입니다.

## 5.2 장애 대응

| 증상 | 확인 | 조치 |
|---|---|---|
| 로그인 화면에 "서버에 연결할 수 없습니다" | Apps Script › 실행 기록에 오류가 있는지, `VITE_API_URL`이 맞는지 | 배포 관리에서 최신 버전이 활성인지 확인. `checkConfiguration` 실행 |
| "INTERNAL_ERROR (오류 코드 E…)" | Apps Script › 실행 기록에서 같은 오류 코드 검색 | 스택 추적으로 원인 확인. 이전 버전으로 배포 롤백 |
| 모든 사용자 로그인 실패 | Firebase 콘솔 › Authentication 상태, Identity Toolkit API 사용 설정 여부 | `checkConfiguration` 결과의 Authentication 항목 확인 |
| 할당량 초과 | Apps Script 대시보드 할당량, Firebase 사용량 | 자정(태평양 시간) 이후 복구. 반복되면 5.1의 유료 전환 검토 |
| 특정 서비스만 실행 불가 | 서비스 상태(점검·비활성·종료일), 사용자 권한, 접속 기록의 오류 코드 | 상태·권한 수정. 저장 즉시 반영 |
| 업무 서비스에서 "통합 로그인이 필요합니다" | 오류 코드 확인(CODE_EXPIRED·CODE_REUSED·INVALID_SERVICE_KEY) | 포털에서 다시 실행. 키 오류면 키를 재발급하고 스크립트 속성 갱신 |
| 연동 후 업무 서비스 장애 | — | 해당 Apps Script의 `PROFCYS_AUTH_MODE`를 `off`로 바꾸면 즉시 원복(재배포 불필요) |
| 관리자 비밀번호 분실 | — | `enableAdminRecovery` 실행 후 `/recover` |
| 화면이 이전 버전으로 보임 | — | 새로고침 안내 배너 클릭 또는 강력 새로고침 |
| 플랫폼 전체 점검 필요 | — | 시스템 설정 › 점검 모드 (최고관리자 외 차단) |

## 5.3 정기 점검 (권장)
- **자동(`installMaintenanceTriggers` 설치 시)**:
  - 매일 03시: 만료 세션·코드·로그 정리
  - 매일 04시: 통계 내보내기
  - 매주 월요일 05시: Sheets 백업
- **매주**: 관리자 홈의 "점검·검토 필요" 목록, 로그인 실패 급증 여부를 확인합니다.
- **매월**:
  - 만료 예정 계정(사용자 목록 › 30일 이내 만료) 확인
  - 퇴사자 비활성화
  - JSON 백업을 내려받아 보관
- **분기**: 관리자 계정 비밀번호 변경, 허용 도메인 목록 검토, 보안 점검표(06 문서) 재확인.
