# 2. 설치·배포 가이드 (Firebase 무료 요금제)

> 이 문서의 모든 단계는 **무료(Spark) 요금제** 범위에서 진행합니다. 다음 작업은 관리자 승인 없이 하지 마세요.
> - 결제 계정 연결
> - Blaze 전환
> - 유료 API 활성화
> - 맞춤 도메인 구매
>
> 진행 상태는 정확히 구분합니다. "배포 준비 완료"는 코드와 설정 파일이 준비된 상태이고, "배포 완료"는 아래 7단계까지 실제로 실행해 `https://profcys.web.app`에 접속이 확인된 상태입니다.

## 0. 준비물

- Firebase 프로젝트 `profcys`의 소유자 Google 계정. 이 계정으로 Apps Script도 만듭니다.
- PC에 Node.js 20 이상, Git.
- Firebase CLI: `npm install -g firebase-tools`, 그다음 `firebase login`.
- 이 저장소: `git clone https://github.com/profcys/profcys_gate.git`, `cd profcys_gate`, `npm ci`.

## 1. Firebase 콘솔 설정 (무료)

1. https://console.firebase.google.com › `profcys` › 좌측 하단 요금제가 **Spark**인지 확인합니다.
2. **Authentication › 시작하기 › Sign-in method › 이메일/비밀번호 › 사용 설정**에서 *이메일 링크*는 끕니다.
   - 사용자 아이디는 PROFCYS DB에서 관리하며, 인증용 이메일은 시스템이 만든 내부 주소(`u<난수>@profcys.firebaseapp.com`)라 메일이 발송되지 않습니다.
   - **Authentication › 설정 › 사용자 작업**에서 "계정 생성(가입) 허용"을 끄는 것을 권장합니다(자체 회원가입 차단 보강). 관리자 계정 생성은 Apps Script가 소유자 권한의 관리 API로 수행하므로 영향이 없어야 합니다. 이 설정은 실제 환경에서 아직 검증하지 않았으므로, 끈 뒤에는 신규 사용자 등록이 되는지 한 번 확인하세요.
3. **Firestore Database › 데이터베이스 만들기**에서 *프로덕션 모드*, 위치 `asia-northeast3 (서울)`을 선택합니다. 위치는 나중에 바꿀 수 없습니다.
4. **프로젝트 설정 › 일반 › 내 앱 › 웹 앱 추가(</>)**에서 이름 `PROFCYS Portal`로 추가합니다. *Firebase Hosting 설정*은 체크하지 않아도 됩니다.
   표시되는 `apiKey`, `appId`를 메모합니다. 둘 다 공개 클라이언트 값이며 비밀이 아닙니다.

## 2. 게이트웨이 API (Apps Script) 만들기

1. PC에서 `npm run gas:bundle`을 실행합니다. 결과물:
   - `build-gas/gateway-api/` 폴더: 개별 파일
   - `build-gas/gateway-api.bundle.js`: 붙여넣기용 단일 파일
2. https://script.google.com › **새 프로젝트**를 만들고 이름을 `PROFCYS Gateway API`로 지정합니다.
3. **프로젝트 설정(⚙) › "편집기에서 appsscript.json 매니페스트 파일 표시"**를 체크합니다.
4. 편집기에서 다음 두 파일을 채웁니다.
   - `appsscript.json`: `apps-script/gateway-api/appsscript.json` 내용으로 교체
   - `Code.gs`: `build-gas/gateway-api.bundle.js` 전체 내용으로 교체
   - clasp 사용 시에는 위 두 단계 대신 `.clasp.json.example`을 참고해 `build-gas/gateway-api`에서 `clasp push`를 실행합니다.
5. **프로젝트 설정 › 스크립트 속성**에 다음을 추가합니다. 비밀번호나 서비스 계정 키는 넣지 않습니다.

   | 속성 | 값 |
   |---|---|
   | `FIREBASE_PROJECT_ID` | `profcys` |
   | `FIREBASE_WEB_API_KEY` | 1-4단계의 `apiKey` |

6. 편집기 상단에서 함수 `checkConfiguration`을 선택하고 **실행**합니다. 권한 승인 창이 뜨면 소유자 계정으로 허용합니다.
   실행 로그에 다음 세 줄이 모두 나와야 합니다.
   - `✔ FIREBASE_PROJECT_ID`
   - `✔ Firestore 연결 성공`
   - `✔ Firebase Authentication 연결 성공`
7. 함수 `initializeDatabase`를 실행합니다. 기본 설정, 카테고리 9개, 초기 서비스 4개가 **비공개 초안**으로 등록됩니다. 반복 실행해도 안전합니다.
8. **배포 › 새 배포 › 유형: 웹 앱**으로 배포합니다.
   - 설명: `PROFCYS Gateway API v3`
   - 다음 사용자로 실행: **나**
   - 액세스 권한: **모든 사용자**. 로그인 없이 호출 가능하지만 모든 요청은 서버에서 세션·권한을 검증합니다.
   - 배포 후 표시되는 **웹 앱 URL(`…/exec`)**을 메모합니다.
   - 이후 코드를 수정할 때는 *배포 관리 › 기존 배포 편집 › 새 버전*을 사용해 URL을 유지합니다.

> 참고: Apps Script 기본 GCP 프로젝트를 그대로 사용합니다. Firebase Auth 관리 API 호출에는 `X-Goog-User-Project: profcys` 헤더로 할당량 프로젝트를 지정합니다.
> 1-6단계 점검에서 Authentication 오류가 나면 Google Cloud 콘솔(`profcys`) › API 및 서비스에서 **Identity Toolkit API**가 사용 설정되어 있는지 확인합니다. 이 API는 무료입니다.

## 3. 프런트엔드 빌드 설정

```bash
cp .env.example .env.production
# .env.production 편집:
#   VITE_API_URL=<2-8단계 웹 앱 URL>
#   VITE_FIREBASE_PROJECT_ID=profcys
#   VITE_FIREBASE_API_KEY=<1-4 apiKey>
#   VITE_FIREBASE_APP_ID=<1-4 appId>
#   VITE_PORTAL_URL=https://profcys.web.app
npm run build      # 타입 검사 + 프로덕션 빌드 → dist/
```

## 4. Firestore 보안 규칙·인덱스 배포

```bash
firebase use profcys
npm run deploy:rules      # firestore.rules + firestore.indexes.json (TTL 정책 포함)
```

규칙은 브라우저의 모든 직접 접근을 거부하고 `public/revision` 문서 읽기만 허용합니다. 인덱스 생성에는 수 분이 걸릴 수 있습니다.

TTL 정책(로그·세션 자동 삭제)이 콘솔에서 적용되지 않는 경우에는 Apps Script에서 `installMaintenanceTriggers`를 실행합니다. 그러면 매일 정리 트리거가 대신 삭제합니다.

## 5. Firebase Hosting 배포

```bash
npm run deploy:hosting    # = npm run build && firebase deploy --only hosting --project profcys
```

배포가 끝나면 `https://profcys.web.app`과 `https://profcys.firebaseapp.com`(무료 기본 도메인) 둘 다에서 로그인 화면이 열리는지 확인합니다.

**맞춤 도메인**은 도메인 구입 비용이 발생하므로 이번 범위에서 연결하지 않았습니다. 나중에 승인받아 연결할 때는 Hosting › 맞춤 도메인 추가에서 진행합니다. SSL은 무료로 자동 발급됩니다.

## 6. 최초 관리자(profcys) 설정

1. Apps Script 편집기에서 `enableInitialSetup`을 실행하면, 실행 로그에 **30분 유효 1회용 설정 토큰**이 표시됩니다.
2. `https://profcys.web.app/setup`에서 토큰을 입력하고 profcys의 비밀번호를 직접 지정합니다. 비밀번호 조건은 12자 이상, 3종류 이상의 문자입니다.
   - 비밀번호는 Firebase Authentication에만 전달되며, 문서·코드·DB·로그 어디에도 저장되지 않습니다.
   - 토큰은 사용 즉시 삭제됩니다.
3. `/login`에서 `profcys`로 로그인하면 보안 정책에 따라 **비밀번호를 한 번 더 변경**해야 합니다.

비밀번호를 잊었다면 `enableAdminRecovery`를 실행한 뒤 `/recover`에서 재설정합니다. 이 경우 모든 세션이 종료됩니다.

## 7. 초기 서비스 공개 및 운영 시작

1. 관리자 › **업무 서비스 관리**에서 초기 4개 서비스의 URL이 기존 주소와 같은지 확인합니다. URL은 변경하지 않습니다.
2. 각 서비스의 **사용자 권한 지정**에서 이용자를 선택합니다. 역할·기관 기반으로 허용하려면 *수정 › 접근 권한*에서 정책을 설정합니다.
3. **공개 승인**을 누르면 공개 전 확인 사항이 표시됩니다. 내용을 확인하고 승인 체크 후 변경합니다.
4. 관리자 › **신규 사용자 등록**으로 계정을 발급합니다. 임시 비밀번호는 한 번만 표시됩니다.
5. 관리자 › **접속 QR코드**에서 인쇄용 QR을 만듭니다.

## 8. 기존 Apps Script 4종 통합 인증 (선택, 단계적)

`apps-script/shared-auth/README.md`를 따릅니다. 기본은 `monitor` 모드로, 기존 사용자 접속에 영향이 없습니다.

- 직접 URL 차단(`enforce`)은 서비스별로 검증한 뒤에만 전환합니다.
- 전환 전에는 원본 프로젝트·시트를 반드시 백업합니다.

## 9. 로컬 개발·테스트 (Google 계정 불필요)

```bash
npm run dev          # http://localhost:5173 — 실제 서버 코드를 메모리 DB로 실행, 콘솔에 설정 토큰 표시
npm test             # 단위·통합 테스트 (vitest)
npm run build && npm run test:e2e   # 브라우저 E2E (Playwright, Chromium 필요)
```

## 10. 업데이트 배포 절차

1. `npm test`와 `npm run build`가 통과하는지 확인합니다.
2. 서버 코드를 바꿨다면 `npm run gas:bundle`을 실행하고 Apps Script에 반영합니다. 그다음 **기존 배포 편집 › 새 버전**으로 배포합니다. URL은 유지됩니다.
3. `npm run deploy:hosting`을 실행합니다. 사용자는 새로고침 안내를 받습니다(서비스 워커).
4. 문제가 생기면 다음과 같이 되돌립니다.
   - Hosting: 콘솔 › Hosting › 출시 기록에서 이전 버전 **롤백**
   - Apps Script: 배포 관리에서 이전 버전 선택
