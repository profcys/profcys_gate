# PROFCYS 통합 인증 공통 모듈 (기존 Apps Script 4종 적용 가이드)

`ProfcysAuth.js` 한 파일을 각 업무 Apps Script 프로젝트에 추가하면, PROFCYS 포털에서 로그인한 사용자만
서버 측에서 확인된 상태로 업무 화면과 서버 함수를 사용할 수 있게 됩니다.

> 이 모듈은 기존 업무 데이터(시트·드라이브)를 읽거나 바꾸지 않습니다. 기존 URL(배포 ID)도 바뀌지 않습니다.
> **기본값은 `monitor` 모드**로, 적용 직후에도 기존 사용자의 직접 URL 접속은 그대로 동작합니다.
> 직접 URL 차단(`enforce`)은 포털 경유 접속을 검증한 뒤 관리자가 직접 전환합니다.

## 대상 서비스

| 서비스 ID | 서비스 | 기존 URL (변경 금지) |
|---|---|---|

## 적용 전: 원본 백업 (필수)

1. Apps Script 편집기 › **개요(ⓘ)** › **프로젝트 복사**로 사본을 만듭니다. 사본 이름에 날짜를 붙입니다. 예: `공통작업 플랫폼 백업 2026-11-26`.
2. 편집기 › **배포 › 배포 관리**에서 현재 웹앱 배포의 **버전 번호**를 기록해 둡니다. 문제가 생기면 이 버전으로 되돌립니다.
3. 연결된 스프레드시트도 **파일 › 사본 만들기**로 백업합니다. 모듈은 시트를 수정하지 않지만, 안전을 위해 백업합니다.

## 적용 절차 (서비스마다 반복)

1. PROFCYS 관리자 화면 › **업무 서비스 관리** › 해당 서비스의 🔑 **통합 인증 키**를 발급합니다. 이때 재인증이 필요하며, 키는 한 번만 표시됩니다.
2. Apps Script 편집기 › **프로젝트 설정 › 스크립트 속성**에 다음 값을 추가합니다. 키를 코드에 적지 마세요.

   | 속성 | 값 |
   |---|---|
   | `PROFCYS_GATEWAY_URL` | 게이트웨이 API 웹앱 URL (`…/exec`) |
   | `PROFCYS_SERVICE_ID` | 위 표의 서비스 ID |
   | `PROFCYS_SERVICE_KEY` | 1단계에서 발급한 키 (`pk_…`) |
   | `PROFCYS_PORTAL_URL` | `https://profcys.web.app` |
   | `PROFCYS_AUTH_MODE` | `monitor` (처음에는 반드시 monitor) |

3. 파일 추가(＋ › 스크립트) › 이름 `ProfcysAuth` › `ProfcysAuth.js` 내용을 붙여넣습니다.
4. 기존 `doGet`(과 `doPost`)를 `example/Code.js`처럼 `ProfcysAuth.handle(e, render_)`로 감쌉니다.
   - 화면을 만드는 기존 코드는 그대로 `render_` 안으로 옮깁니다.
   - HTML 템플릿 `<head>`에 `<?!= ProfcysAuth.clientScript(profcysToken) ?>`를 추가합니다.
5. 보호할 서버 함수(시트 읽기·쓰기 등)의 첫 인자로 `token`을 받고, 첫 줄에 `var user = ProfcysAuth.require(token);`를 추가합니다.
   클라이언트의 `google.script.run.fn(a, b)` 호출은 `PROFCYS.run('fn', a, b)`로 바꿉니다.
6. 편집기에서 `profcysSelfTest` 함수를 실행해 `gateway: reachable, service key accepted`가 나오는지 확인합니다.
   처음 실행할 때 외부 요청(UrlFetch) 권한을 승인합니다.
7. **배포 › 배포 관리 › 기존 배포 편집 › 새 버전**으로 배포합니다. 새 배포를 만들면 URL이 바뀌므로 반드시 *기존 배포를 편집*합니다.
8. PROFCYS 관리자 화면에서 해당 서비스를 다음과 같이 바꿉니다.
   - 실행 방식: **인증 연동 후 실행(SSO)**, 전달 방식: **POST**
   - 연동 상태: **통합 인증 적용 (직접 접근 차단 미검증)**
9. 일반 사용자 계정으로 포털에서 실행해 정상 동작을 확인합니다. 관리자 › 접속 기록에 *서비스 인증 성공*이 남는지도 봅니다.
10. 확인이 끝나면 `PROFCYS_AUTH_MODE`를 `enforce`로 바꿉니다. 시크릿 창에서 기존 URL로 직접 접속했을 때 차단 화면이 나오는지 확인한 뒤,
    관리자 화면에서 직접 URL 접근을 **차단 확인**, 보안 검증을 **완료**, 연동 상태를 **완전한 통합 인증 완료**로 바꿉니다.

## 되돌리기

- 즉시 원복: 스크립트 속성 `PROFCYS_AUTH_MODE`를 `off`로 바꿉니다. 재배포 없이 바로 반영됩니다.
- 완전 원복: 배포 관리 › 기존 배포 편집 › 적용 전에 기록한 버전을 선택합니다.

## 보안 동작 요약

- 인증 코드: 64자리 난수, 60초 유효, 1회용, 서비스 ID에 고정됩니다. 다른 서비스나 재사용 시에는 거부됩니다.
- 코드 교환은 **서버 간 통신**(UrlFetchApp → 게이트웨이)으로만 이루어지며, 서비스 키 원문은 게이트웨이 DB에 저장되지 않습니다(해시만 저장).
- 서비스 세션은 CacheService에 최대 6시간 보관되며, 5분마다 게이트웨이 `sso.check`로 다음 상태를 재확인합니다.
  - 계정 비활성·만료
  - 권한 회수
  - 강제 로그아웃·로그아웃
  - 서비스 점검·중지
- 게이트웨이와 15분 이상 통신하지 못하면 보호 함수 호출을 차단합니다(fail-closed).
- `monitor` 모드에서는 포털을 거치지 않은 직접 접속이 기존처럼 허용됩니다. 따라서 이 상태를 "완전한 통합 인증"으로 표시해서는 안 됩니다.

## 알려진 제약

- Apps Script 웹앱은 쿠키를 쓸 수 없습니다. 새로고침하면 서비스 세션 토큰이 사라지므로, 포털에서 다시 실행해야 합니다.
  POST로 전달된 코드는 재전송되더라도 1회용이므로 거부됩니다.
- "Google 계정 로그인 필요"로 배포된 웹앱은 Google 로그인과 PROFCYS 인증이 모두 필요합니다.
- 웹앱이 "웹앱에 액세스하는 사용자" 권한으로 실행되는 경우, 사용자마다 처음 한 번 외부 요청 권한을 승인해야 합니다.
